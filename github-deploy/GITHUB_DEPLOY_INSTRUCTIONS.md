# Инструкция по публикации сайта на GitHub Pages

## Что было исправлено

### 1. Проблема: белый экран
Причина: GitHub Pages не поддерживает клиентскую маршрутизацию (client-side routing), которую использует React SPA. При обновлении страницы или переходе по прямой ссылке сервер возвращает 404 ошибку.

Решение:
- Добавлен файл `404.html` — перехватывает все неизвестные запросы и перенаправляет на `index.html`
- Добавлен SPA-скрипт в `index.html` — восстанавливает оригинальный путь после редиректа

### 2. Проблема: устаревшие GitHub Actions (Node.js 20)
Причина: actions/checkout@v4, actions/configure-pages@v5 и actions/upload-artifact@v4 использовали Node.js 20, который устарел.

Решение:
- Обновлен workflow с `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true`
- Заменен `actions/upload-pages-artifact@v4` на `actions/upload-pages-artifact@v3` (стабильная версия)
- Используется `actions/deploy-pages@v4` для деплоя

## Пошаговая инструкция по публикации

### Шаг 1. Создайте репозиторий на GitHub

1. Зайдите на https://github.com и авторизуйтесь
2. Нажмите зеленую кнопку **"New"** (или "+" в правом верхнем углу → "New repository")
3. Введите имя репозитория, например: `e-pravo-site`
4. Выберите **"Public"** (публичный) — GitHub Pages бесплатен только для публичных репозиториев
5. Нажмите **"Create repository"**

---

### Шаг 2. Загрузите файлы сайта

Есть два способа:

#### Способ А. Через веб-интерфейс (проще для новичков)

1. Откройте страницу созданного репозитория
2. Нажмите **"uploading an existing file"**
3. Перетащите ВСЕ файлы сайта (index.html, папку assets/ и т.д.) в область загрузки
4. В разделе "Commit changes" введите сообщение: `Initial commit`
5. Нажмите **"Commit changes"**

#### Способ Б. Через командную строку (терминал)

```bash
# 1. Перейдите в папку со своим собранным сайтом
cd путь/к/папке/сайта

# 2. Инициализируйте git-репозиторий
git init

# 3. Добавьте все файлы
git add .

# 4. Создайте первый коммит
git commit -m "Initial commit"

# 5. Подключите удаленный репозиторий (замените USERNAME на свой логин)
git remote add origin https://github.com/USERNAME/e-pravo-site.git

# 6. Отправьте файлы на GitHub
git branch -M main
git push -u origin main
```

---

### Шаг 3. Создайте структуру репозитория

В корне репозитория должна быть такая структура:

```
e-pravo-site/
├── .github/
│   └── workflows/
│       └── deploy.yml          ← файл из папки .github/workflows/
├── assets/
│   ├── index--2vVGyMx.js       ← ваш JS-файл
│   └── index-CDZa_tFs.css      ← ваш CSS-файл
├── 404.html                    ← файл из этой инструкции
└── index.html                  ← обновленный файл
```

Важно: папка `.github` начинается с точки — это системная папка GitHub.

---

### Шаг 4. Включите GitHub Pages в настройках

1. Откройте репозиторий на GitHub
2. Перейдите в **"Settings"** (вкладка вверху)
3. В левом меню выберите **"Pages"**
4. В разделе **"Build and deployment"** установите:
   - **Source:** GitHub Actions
5. Нажмите **"Save"**

---

### Шаг 5. Запустите деплой

1. Перейдите во вкладку **"Actions"** в вашем репозитории
2. Вы увидите workflow "Deploy to GitHub Pages"
3. Если он не запустился автоматически:
   - Перейдите в **"Actions"** → **"Deploy to GitHub Pages"**
   - Нажмите кнопку **"Run workflow"** → **"Run workflow"**
4. Дождитесь зеленой галочки (обычно 1-2 минуты)

---

### Шаг 6. Проверьте сайт

1. Перейдите снова в **"Settings"** → **"Pages"**
2. Там будет ссылка на ваш сайт, например:
   `https://USERNAME.github.io/e-pravo-site`
3. Перейдите по ссылке — сайт должен открыться

## Если сайт все еще не работает

### Проблема: сайт открывается, но страница белая

1. Откройте консоль разработчика (F12 → Console)
2. Если видите ошибки 404 для JS/CSS файлов:
   - Убедитесь, что папка `assets/` загружена в репозиторий
   - Проверьте, что в `index.html` пути начинаются с `./` (точка-слэш)

### Проблема: "Actions" не запускается

1. Перейдите в **"Settings"** → **"Actions"** → **"General"**
2. В разделе "Actions permissions" выберите:
   - **"Allow all actions and reusable workflows"**
3. Нажмите **"Save"**

### Проблема: ошибка доступа при деплое

1. Перейдите в **"Settings"** → **"Pages"**
2. Убедитесь, что выбрано **"GitHub Actions"** в качестве источника
3. Проверьте, что репозиторий публичный (Public)

### Проблема: обновления не появляются на сайте

GitHub Pages кеширует сайт. Подождите 2-5 минут после деплоя.
Для принудительного обновления добавьте `?nocache=1` к URL.

## Обновление сайта

Когда нужно обновить сайт:

1. Соберите проект заново (npm run build)
2. Замените файлы в папке `assets/` новыми
3. Закоммитьте и запушьте изменения:

```bash
git add .
git commit -m "Update site"
git push
```

Деплой запустится автоматически.
